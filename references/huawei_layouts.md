# Huawei Layout Catalog — 版式原型与密度基准

> 蒸馏自 58 张真实华为汇报页（`assets/huawei_layout_catalog.json`，含每张卡的结构指纹/密度/代表标题）。
> 生成内容页前先在此选型：按内容语义挑原型 → 按密度基准填充 → 再写 pptxgenjs 代码。禁止照抄原始坐标。

## 密度基准（真实页统计，偏离即不像华为）

| 指标 | 区间 | 中位 |
|---|---|---|
| 每页中文字数（含标题） | 300–1160 | **≈600** |
| 文本形状数 | 11–77 | **≈33** |
| 分带数（横向区块行数） | 2–5 | 3 |
| 图片数（小图标，非配图） | 0–13 | **2** |
| 图片面积占比 | ≤0.5%（最大 30%，仅封面类） | 0.5% |
| 表格 | **0/58 页使用表格** —— 对比信息一律用卡片矩阵 | — |
| 连接线 | 流程/架构页 6–14，普通页 0–2 | 1 |

结论：真实华为高管页 = 高密度卡片阵 + 小图标点缀；不是稀疏大图页，也不是表格页。

## 六个版式原型（按内容语义选择）

### A1 · 3列卡片阵（主力原型，约 40% 的真实页）
代表卡：`template_slide_007 / 009 / 012 / 013 / 037 / 040`
- 结构：标题(0.2"–1.0") + 右上角红底白字 tag + 3列×2~3行卡片矩阵 +（约 1/3 的页有）底部结论带
- 每卡：小标题(加粗) + 1–3 行正文；卡内 15–25 字
- 适用：三类并列要素、H1/H2/H3 假设、方案三支柱、适用场景/收益
- pptxgenjs 骨架：`三列 w≈3.9" 卡片，行高 1.1"–1.3"，卡间距 0.12"`

### A2 · 2列左右分栏 + 堆叠块
代表卡：`template_slide_005 / 008 / 011 / 016 / 028 / 034`
- 结构：左栏(40–55%)大块或层级列表，右栏 2–3 个堆叠卡片/步骤；常见底部结论带
- 适用：方法×收益、左原则右案例、输入输出对照
- 骨架：`左 w≈5.6" 右 w≈6.4"，右侧块高按内容 1.2"–2.0" 递增堆叠`

### A3 · 4列+密集架构阵（解决方案架构页）
代表卡：`template_slide_003 / 027 / 029 / 048 / 056`
- 结构：4–5 列 × 3–5 带的矩阵，顶部横带是分层标签（L5–L12 技术栈、平台层/应用层），交叉格为能力卡
- 图标多（5–13 个，每卡一个小图标）；连线表达层间支撑
- 适用：技术栈分层、解决方案架构、体系全景
- 骨架：`列 w≈2.9"，每带左侧 0.9" 层标签列 + 右侧卡片`

### A4 · 全宽横带叙事（案例页/洞察页）
代表卡：`template_slide_001 / 010 / 045 / 046 / 050 / 058`
- 结构：2–4 个全宽横带，每带 = 小节标题(红/加粗) + 图标行或正文带；字数可到 800–1160
- 适用：客户案例（背景→痛点→方案→收益）、深度洞察、单主题多论点
- 骨架：`带高 1.2"–1.8"，小节标题 12pt 红加粗左对齐`

### A5 · 中心辐射 hub（机制/生态页）
代表卡：`template_slide_005(连线1) 以外的 connector≥6 卡：003/056 等`
- 结构：中心概念 + 6–8 个卫星要素卡，连线表达关系；卫星卡小而等距
- 适用：机制分析、生态全景、飞轮
- 骨架：`中心 w≈3.2" 居中，卫星 2.0"×1.0" 环形/两翼排布`

### A6 · 时间线/路线图
代表卡：`template_slide_023 / 026`（5带 纵向阶段）
- 结构：横向 3–5 阶段时间轴，每阶段 = 节点圆点 + 阶段卡（标题+2–3行）；或纵向阶段带
- 适用：路线图、实施计划、演进路径
- 骨架：`轴线 y 居中 w=11.9"，节点间距等分，阶段卡 2.6"×1.4"`

## 通用硬规则（自 requirements.md，实战提炼）

1. **标题 = 直接结论**（"AI人才供给不足已成为研发组织扩张的核心瓶颈"式），禁用"趋势判断："等前缀；标题 22–26pt 粗体
2. **右上角 tag**：红底白字分类标签（如"方案收益"），约 1/2 真实页携带
3. **底部结论带**：约 1/3 页有，浅红底 + 左侧红竖条，一句话结论加粗
4. **红色纪律**：红只用于 标题关键词/tag/关键数字/卡片左竖条/结论带；正文黑 #000000、辅助灰 #595959
5. **卡片优于表格**：任何对比/矩阵信息用卡片阵表达；真实 58 页 0 表格
6. **图标小而克制**：图标是 0.3"–0.5" 的点缀（每卡一个），不是配图；全页图片面积 ≤5%
7. **信息密度**：每页 500–800 字、2–4 个 section、每 section 2–5 个 bullet；低于 300 字的页不像华为
8. **事实边界**：所有数字/事实来自用户输入；输入不足时显式标注 evidence_gap，不得编造

## 与生成流水线的配合

1. 读用户素材 → 判定语义类型 → 在本文档选 1 个主原型（可 A4 叙事 + 内嵌 A1 卡片阵混排）
2. 打开 `assets/huawei_layout_catalog.json` 找 2–3 张同原型代表卡，核对密度（字数/带数/列数/图标数）
3. 按"密度基准"填充内容，超出 800 字先压缩措辞再考虑加带
4. 写 pptxgenjs 内容页（参考上方骨架尺寸）→ 套壳 → 渲染 QA
